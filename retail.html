Retail Behavior Analysis

SQL based customer behavior inference model. Uses past data to predict secondary customer departments, validating against current/future data engagement system.

Postgres CTEs Subquery Window Functions Aggregation Power BI

Create and Insert customer_orders Table

Transactional custoner behavior. Order status: completed or returned. Department. Order date and value.

Create and Insert customer_activity_tracking Table

Captures customer activity; departments, repurchases, promotion redeemed, enagagement with departments overtime.

Query the Data

  • Grouped by each customer and department, retrieve total transactions (completed and returned alike), total completed orders, and total returned orders. In a 3 month timeframe, starting 3 months prior to current date.
  • Use dense_rank (to include department activity ties) and return the top 2 most engaged departments per customers.
  • Map inferred departments of interests per custoner, based on the top 2 most engaged departmetns.
  • Union actual to inferred behavior with each row labeled as "actual" or "inferred".
  • Join the unioned table t the future behvaior of total activity in department, total repurchases and total promotions redeemed per customer. "Future Behavior" defined as current month going back 3 months.
